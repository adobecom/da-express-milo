# MWPW-210450: Global Navigation Breadcrumb Compatibility

## Objective

Validate the new global navigation across pages with and without GNAV breadcrumbs, including localized routes and fallback behavior. The page inventory below is ordered so the ten highest-priority regression pages are exercised first.

## Highest-priority pages

| Priority | Page | Coverage reason |
|---:|---|---|
| 1 | `/express/` | Homepage; highest-traffic no-breadcrumb layout |
| 2 | `/express/templates` | Template-X entry; in-page breadcrumbs are separate from GNAV breadcrumbs |
| 3 | `/express/pricing` | Conversion-critical pricing page |
| 4 | `/express/create` | Core creation hub |
| 5 | `/express/business` | Business landing page with navigation variants |
| 6 | `/express/business/teams` | High-value teams conversion page |
| 7 | `/express/photos` | Root-level page that renders a GNAV breadcrumb |
| 8 | `/express/feature/image/resize` | High-traffic quick action with mixed locale/fallback behavior |
| 9 | `/express/create/logo` | High-traffic SEO page that renders a GNAV breadcrumb |
| 10 | `/express/print` | Print hub and entry to breadcrumb-heavy generated PDPs |

## Locale compatibility coverage

The priority set was crawled across all 19 primary locale prefixes from the Express sitemap index at 1440 × 900 and 390 × 844.

- 190 locale/page combinations requested.
- 164 combinations rendered `header.global-navigation.ready`.
- 12 rendered `nav.feds-breadcrumbs`.
- All 12 breadcrumb cases still matched `nav:not(:has(> .feds-breadcrumbs))`.
- 142 desktop dropdowns opened without vertical or horizontal viewport overflow.
- All 18 applicable mobile drawers opened, fit their intended viewport or gutter, and locked body scrolling.
- Arabic uses a thin ACOM navigation without a hamburger drawer and rendered correctly in RTL.
- 55 requests changed URL through locale fallback or production redirects.
- Four Simplified Chinese routes returned direct 404 responses: `/cn/express/templates`, `/cn/express/create`, `/cn/express/create/logo`, and `/cn/express/print`.
- Template routes redirected to `www.adobe.com`; the production edge returned 403 to the headless crawler, so those runtime paths require an approved production-browser check.

## Compatibility finding

The breadcrumb is wrapped as a sibling of the top navigation:

```html
<div class="feds-topnav-wrapper">
  <nav class="feds-topnav">...</nav>
  <div class="feds-breadcrumbs-wrapper">
    <nav class="feds-breadcrumbs">...</nav>
  </div>
</div>
```

Therefore, the following selector misclassifies pages that render breadcrumbs:

```css
header.global-navigation nav:not(:has(> .feds-breadcrumbs))
```

Breadcrumb absence must be evaluated at the header scope, and the rule must target `nav.feds-topnav` explicitly:

```css
header.global-navigation:not(:has(.feds-breadcrumbs))
  nav.feds-topnav:not(:has(
    .feds-popup.is-open:not(.small-menu),
    .feds-menu-wrapper.is-open
  )) {
  --feds-popup-bg-height: 100%;
}
```
